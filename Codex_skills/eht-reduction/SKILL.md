## Start or resume

Locate the project by its README.md and tools/instructions/Markdowns directory. Resolve paths from that root even when the skill was installed elsewhere. Select the requested observation by inspecting data/ recursively for the named UVFITS, calibration_tables or picard.out. Examples, working observations and workflow tests may share filenames. Confirm the target, band and reduction run before using its files. If the project is unavailable, request its checkout path. Read the observation's inspection/HANDOFF.md when present.

Inventory the actual input paths and record which file supplies each quantity, its units, timestamps, scan IDs and flags. Match diagnostics to the science run. Take scan IDs and bounds directly from stored metadata where available; distinguish measured first/last integrations from scheduled boundaries. Inspect original inputs read-only. Resolve obsolete paths in historical scripts before any application of flags.

## Choose the procedure

Unlinked flagging guide names below are relative to tools/instructions/Markdowns/flaggings/. Use the shared code index at tools/ancillary_py_codes/README.md. Use [Overall_workflow.md](../../tools/instructions/Markdowns/flaggings/Overall_workflow.md) for the rPICARD stage order. Write calibration proposals and checkpoints in the observation’s inspection directory and visibility proposals alongside the visibility data.

- **Inspection PDFs.** Read the [PDF writing and layout guide](../../tools/instructions/Markdowns/inspection_pdf_style.md) alongside the relevant product guide. Open with an array-wide survey of what was checked, including phase and amplitude for passbands or the delay distribution and phase coverage for delay. Present the measured trigger before any rerun recommendation. Render the pages and verify that the selectable commands retain their exact arguments.
- **Pipeline inspection.** Start with picard.out and its matching diagnostics directory. Record the stage, affected data, evidence and consequence of unusual events. Use the project's CASA_rPICARD data inspection slides in tools/instructions/PDFs/ for its inspection sequence.
- **Delay.** Follow ff_sb_inspection.md for ff_sb.t. Respect per-solution flags, report delay in ns and phase in degrees, and plot phase only where that same row, hand and SPW have finite, unflagged phase and delay. Label affected hands and SPWs. Record antenna, scan, SPW and receptor for a candidate.
- **Passband.** Follow all_antennas_bandpass_inspection.md. Use bpass_complx.t for phase and bpass_scalar.t for amplitude. Inspect each receptor and antenna across SPWs. Compare candidate jumps or excursions with neighbors, annotate evidence, and distinguish wrapped phase from a physical discontinuity.
- **Calibration flags.** Follow [delaypassbandflag_guide.md](../../tools/instructions/Markdowns/flaggings/delaypassbandflag_guide.md) for Codex proposals and copy verification, then for the human queue review and all-antenna examination. Keep delay and passband exports separate and target each loaded table.
- **Visibility.** Before imaging, use [visflag_guide.md](../../tools/instructions/Markdowns/flaggings/visflag_guide.md) for Codex proposals, human queue review and the second pass with `--examine` and visibility_inspection_guide.md for provenance, figures and page design. Inspect UVFITS axes and frequency metadata; verify the dimensions of any matching MS or channel-resolved diagnostic. Plot individual channels at their measured frequencies. Report missing spectra and the actual resolution where only IF averages exist. Compare independent baselines before proposing an antenna-wide flag. Identify incomplete polarization by affected products, time and SPW. Use the guide's RR/red, RL/green, LR/blue, LL/dark-slate convention. Lead with measured findings and controls, then a scan inventory. Present annotated command evidence followed by all observations with proposed selections masked before averaging.
- **Rerun advice.** When asked about recalibration or when an inspection finding meets the project’s restricted eligibility conditions, follow the [rerun advice guide](../../tools/instructions/Markdowns/AI_advices/rpicard_rerun_advice.md). Tie each proposed working-input edit to observed evidence and a before/after test. Distinguish executed task arguments from the host launcher and the training template. Preserve the reference task range, flag state and calibrator-to-science handoff apart from the proposed change. Show the exact diff and working directory, identify host-only details, and test for stale calibration reuse in the proposed acceptance checks. Treat execution as a separate human decision.
- **Interactive review.** Read tools/ancillary_py_codes/visflag_widget/README.md. Launch app.py from the observation directory with the actual input and an explicit review output. PDF or ASCII input opens a command queue; --examine also permits browsing all data. Keep proposed selections, reviewer approvals and confirmed CASA application distinct. Export individual formal CASA calls targeting the verified ordinary MS or loaded calibration table. Confirm selection semantics and channel mapping on that target before application. Preserve the UVFITS.

## Close or pause

Record input and output paths relative to the observation, verified dimensions, missing coverage, substantive findings and their evidence, and the next actionable step in inspection/HANDOFF.md. Record whether commands were proposed, approved, applied or independently verified, including the target of any test. Approval in a rehearsal applies only to that rehearsal. Before reusing a checkpoint verify its inputs and selection settings. Use the M87 example for style; derive measurements, flag commands and provenance anew.
