# Inspect calibrated visibilities across all scans and baselines

For the shared scripts and commands to start a new observation under `data/`, see the [inspection code directory](../../../ancillary_py_codes/README.md).

Use this procedure for one calibrated source at a time. The inspection unit is **one cross-correlation baseline in one original observing scan**. Review all units before deciding which problems can be attributed to an antenna. Use the original **M87_full_visibility_inspection.pdf** as the visual reference for symbols, axes, captions and diagnostic overlays. The revised report order below supersedes its all-baselines-first pagination.

## 1. Establish coverage and provenance

1. Identify the calibrated UVFITS file, the matching reduction’s observing log (`list.obs`), and the source’s scan-specific frequency diagnostics. For this reduction, the inputs are `M87_calibrated.uvf` and `diagnostics_2026-09-16_15-00-11/`. If available, also identify the original calibrated, channelized Measurement Set (MS) and its calibrated visibility column. Record the file actually used for each view.
2. Read the source, station numbers and names, UTC timestamps, frequency setups, polarizations, weights, amplitude unit, and channel grid from the headers and tables. Preserve baseline orientation. For a reversed baseline, conjugate the visibility and exchange RL and LR together when putting it into a common orientation. Keep the stored orientation for translating findings back into CASA selections.
3. Prefer an explicit scan identifier in the visibility data. For a UVFITS export without one, match source and timestamp against independently identified scan intervals. In this reduction those intervals and original IDs come from the observing log. For this export, include timestamp centers up to 0.010 s beyond the rounded log end. Verify that every record maps to precisely one scan. Use the input timestamp precision to set the tolerance for a new observation. Check for unassigned records and ambiguous overlaps. A source-only UVFITS import can renumber scans. Keep the original scan ID for titles and the verified target-MS selection for commands.
4. For each scan, enumerate the distinct station pairs from the participating antennas. Record which pairs have valid data, only flagged/invalid data, or no records. Count integrations and valid samples by correlation and spectral window (SPW). An absent station or baseline is a coverage entry, not evidence of a failure. Use this inventory to reconcile the final report.

## 2. Build both views from the same selections

Accept finite complex visibilities with finite, positive weights. For an MS, honor sample flags and row flags as well. Keep the excluded counts. For coherent averages use `sum(w × V) / sum(w)` separately for each hand, then take the modulus and wrapped phase. Leave an empty bin blank. The phase of a zero-amplitude mean is undefined.

| Panel | Averaged page | Less-averaged page |
| --- | --- | --- |
| Amplitude and phase versus time | Use 4-second bins anchored at the original scan start. Average the sampled frequencies within each bin. Label time in seconds from an explicit UTC start. | Draw each valid exported integration, IF, and polarization at its actual timestamp. Record the measured cadence. In the preview it was about 0.4 s. |
| Amplitude and phase versus frequency | Within the scan, form one weighted complex mean per exported IF and hand. Plot it at the IF center in GHz. | Preserve individual channel frequencies. With a channelized MS, average complex visibilities **over time only** within each channel and hand. Alternatively, recover the corresponding scan-level channel spectrum from the saved rPICARD diagnostic. |

For an rPICARD PostScript spectrum, identify its page by **source, scan, and printed baseline**. Calibrate the coordinates from that page’s labeled ticks, match colors to its own polarization legend, and verify that the recovered markers land on the observing log’s channel grid. Check spacing, sideband order, SPW boundaries, missing points, and amplitude/phase pairing. Record the diagnostic filename and page. The recovered amplitudes and phases have the precision of the plotted coordinates and carry no per-integration weights.

The M87 export holds one frequency per IF. The preview’s diagnostic resolves 32 windows with 116 channels per window at 0.5 MHz spacing. Read those quantities anew for other data. If a matching fine spectrum is unavailable, label the available IF resolution and record the gap. Never spread IF points across invented channel frequencies. Use the amplitude unit of each input. This UVFITS header says `UNCALIB`, while the diagnostic labels its amplitude in Jy.

## 3. Paginate the cleaned coverage sequence

After the command evidence sequence, process scans in time order. Within each scan, sort baselines in a stable order and take up to six at a time. Give each group **two consecutive pages**, averaged first and less-averaged second. Use the same baseline in the same cell on both pages. Start a fresh group when the scan changes.

| Row of the 4 × 3 grid | Left | Middle | Right |
| --- | --- | --- | --- |
| 1 · time | Baseline 1 | Baseline 2 | Baseline 3 |
| 2 · frequency | Baseline 1 | Baseline 2 | Baseline 3 |
| 3 · time | Baseline 4 | Baseline 5 | Baseline 6 |
| 4 · frequency | Baseline 4 | Baseline 5 | Baseline 6 |

Each occupied cell has **amplitude above phase** and the baseline and original scan ID in its title. Use small solid dots and one consistent legend: RR red (`#EE2C2C`), RL green (`#2E8B57`), LR blue (`#0000FF`), and LL dark slate (`#314F4F`). Plot phase in degrees. Preserve full amplitude excursions and actual data gaps. Use the compact frequency plot only. Leave unused slots in the last group empty. For an expected baseline with entirely invalid data, label its status explicitly or account for it in the coverage index.

Use amber shading for suspect time intervals, pale bands for suspect SPWs, and open rings for narrow spectral peaks. Apply marks to the relevant panels and hands only. Identify features in the notes by page, UTC interval or frequency, SPW/channel, and polarization so a reader can locate a small mark.

## 4. Identify and localize problems

- **Amplitude jumps, dropouts, and isolated points.** Compare the candidate with adjacent integrations and a stable part of the same scan and hand. Quantify the amplitude ratio, duration, number of valid samples, and scatter. Compare individual amplitudes with the coherent means. A small coherent mean can result from cancellation when phases scatter.
- **Phase jumps and residual slopes.** Measure phase changes with circular differences. A display crossing at ±180° can be continuous. Check signal strength, uncertainty, and persistence in shorter time segments. For a credible phase slope, fit phase against frequency over usable contiguous channels, inspect SPW-edge steps separately, and report the slope, frequency span, and hand. For slope in degrees/GHz, the corresponding delay in ns is the slope divided by 360, with the sign tied to the stated baseline convention.
- **Spectral spikes and window-wide errors.** Compare each channel with nearby channels and a robust within-window reference, separately by hand. Record peak-to-median ratio, channel width, and SPW/channel index. Check whether the same edge channel recurs across windows and whether a broader offset persists after omitting the spike. The preview’s numerical thresholds are examples; noise, SNR, and the number of comparisons determine how credible a new candidate is.
- **Antenna attribution.** For each candidate, compare simultaneous baselines sharing each endpoint and contemporaneous baselines excluding it. Align UTC, physical frequency, hand, and resolution. Look for a consistent onset, recovery, spectral feature, or signed phase pattern on independent partners. In the ordered baseline A–B, an A-side R-feed problem can affect RR and RL; a B-side R-feed problem can affect RR and LR. Account for orientation before pooling evidence. Record which partners support or contradict the attribution and which have insufficient SNR.
- **Disposition.** Distinguish an antenna/feed candidate, a baseline-only candidate, and a feature needing further inspection. Consider resolved source structure, a visibility null, weak cross-hands, and known calibration behavior before proposing a flag. Check gain, delay, or bandpass diagnostics for the same station and interval where available. With only one usable partner, leave the antenna attribution open.

## 5. Summarize evidence and propose CASA commands

Open with the findings-first sequence specified below. Include input filenames, source and UTC coverage, averaging choices, amplitude units, analysis date/time with timezone, and actual model and reasoning setting. If usage is requested, give the measured quantity and its scope, or state that it was unavailable. Include a scan-to-page index. After the plots, list each candidate with its measured effect, affected selection, comparison baselines, confidence, page reference, and proposed action. Include noteworthy features that deserve monitoring even when the evidence does not justify a flag.

List **formal, standalone CASA `flagdata(..., mode='manual', ...)` calls, one per justified selection, with no loop**. Present antenna-wide selections supported by multiple partners first. Follow with the remaining baseline-specific selections and remove redundant coverage. A station-wide hand selector can affect different feeds when that station switches position in the stored baseline order. Verify its effect across both orientations and split selections when needed.

Name the exact target MS for each command group. Verify `field`, station names, correlation labels, SPW IDs, channel indices, and scan ID or UTC `timerange` in that target. A single original channel and an entire IF in an imported UVFITS MS are different selections. Restrict each proposed command to the time, frequency, and hands supported by the evidence. Test on a disposable copy when available, compare the changed flag cells with the intended mask, and identify any untested command. Keep the science inputs read-only during inspection.

## 6. Reuse the code and verify the report

The [preview renderer](../../../ancillary_py_codes/visibility/visibility_preview.py) handles one baseline and scan. The [diagnostic spectrum reader](../../../ancillary_py_codes/visibility/diagnostic_spectrum.py) recovers channel markers. The [review settings](../../../ancillary_py_codes/visibility/NN_PV_scan2_review.json) illustrate how to record boundaries, tick anchors, annotations, and commands. To reproduce the approved case from the observation’s inspection directory with Python, NumPy, Astropy, and Matplotlib:

```sh
scripts="$(git rev-parse --show-toplevel)/tools/ancillary_py_codes/visibility"
python3 "$scripts/visibility_preview.py" ../M87_calibrated.uvf "$scripts/NN_PV_scan2_review.json" /tmp/M87_visibility_check.pdf
```

For a full run, use a batch driver that indexes the visibility records once, reuses the averaging and plotting functions, and records each candidate before assigning flags across baselines. Read each diagnostic page’s own scale and legend. Generate new settings and findings for every selection. Write the full report to a separate file in `inspection/` so the approved preview stays available for comparison.

Before delivery, reconcile every scan and baseline against the inventory. Check that each plotted selection appears once in each view and that its time and frequency cells align. Render the PDF and inspect dense pages, partially filled pages, missing-data cases, and pages with flagged candidates. Cross-check plot marks, notes, and CASA commands against the same evidence list. Deliver the report with the reusable analysis code and the information needed to rerun it.

## 7. Run the updated M87 pipeline

The full report is [M87_full_visibility_inspection.pdf](../../examples/M87_full_visibility_inspection.pdf). Run these commands in the observation’s inspection directory. The UVFITS and diagnostic readers use Python with Astropy and NumPy. Matplotlib produces the plot sheets. The last two scripts use ReportLab, pypdf, pypdfium2, NumPy and Pillow. On this Mac those document libraries are in the bundled Codex Python runtime. Use the interpreter containing the dependencies for each command.

```sh
scripts="$(git rev-parse --show-toplevel)/tools/ancillary_py_codes/visibility"
diag=../diagnostics_2026-09-16_15-00-11
python3 "$scripts/index_visibility.py" ../M87_calibrated.uvf "$diag/list.obs" M87_visibility_coverage.csv
python3 "$scripts/collect_visibility_samples.py" ../M87_calibrated.uvf M87_visibility_coverage.csv M87_checkpoints/uv
python3 "$scripts/collect_channel_spectra.py" ../M87_calibrated.uvf "$diag/PLOTS_VISIBILITIES" "$diag/list.obs" M87_checkpoints/channels
python3 "$scripts/assess_visibilities.py" M87_checkpoints M87_visibility_coverage.csv
python3 "$scripts/plan_visibility_flags.py"
python3 "$scripts/full_polarization.py"
python3 "$scripts/render_visibility_scans.py" M87_checkpoints M87_visibility_coverage.csv
python3 "$scripts/assemble_visibility_report.py" --model "ACTUAL MODEL FOR THIS RUN" --output M87_revised_visibility_inspection.pdf
python3 "$scripts/verify_visibility_report.py" M87_revised_visibility_inspection.pdf /tmp/m87_report_review
```

The plan, individual findings, per-scan data arrays, source-page inventory, validation results and plot sheets are in `M87_checkpoints/`. To repeat the CASA verification, create a fresh disposable directory, import the complete M87 UVFITS there as `M87_calibrated.ms` using CASA `importuvfits` with `antnamescheme='old'`, and create an empty `.disposable_flag_test` file in that directory. With that directory as the working directory, run [verify_export_flags.py](../../../ancillary_py_codes/visibility/verify_export_flags.py) using CASA Python and the absolute paths to `M87_checkpoints/flag_plan.json` and `M87_checkpoints/export_flag_audit.json` as its two arguments. It flags only the disposable import and compares the entire FLAG column after each call. The assembler checks that the saved audit matches all current export selections.

The reviewed time intervals, summary prose and decisions about SPW 28 in the flag planner and report assembler are specific to this observation. For a different observation, replace those decisions with its own cross-baseline evidence, calibrate its diagnostic axes, confirm its dates and integration intervals, and record the actual model. Keep each dataset’s checkpoints in its own directory. If the inputs or the review decisions change, regenerate affected plot sheets and repeat the CASA checks before delivery.

## 8. Require all four polarization products

At each ordered baseline, integration timestamp and exported IF, count the hands with finite real and imaginary values and finite positive weights. Count zero as already empty, four as complete, and one through three as partial. For the current export, 38,260 cells have exactly two valid products. They span 27 baseline–scan selections in scans 2, 4, 6 and 8. Use the original input mask before averaging to identify incomplete coverage and illustrate it on the evidence pages. Use the revised masks for the cleaned atlas. Add a magenta bar over the times or IFs with one or more partial cells. Label each affected panel with the products and their exact zero-based spectral window IDs, e.g. “LL/LR missing in SPWs 17, 31”. Group products only when their affected windows match. Use ranges for contiguous windows. Add one sentence between rows on each marked page explaining that the time bar means at least one listed spectral window lacks a product and other windows can still supply points of that color. Keep the coverage table by scan, baseline, missing hands and SPWs to resolve either projection.

Translate each missing correlation into the receptor at each ordered endpoint. Use an antenna selector first where at least two partners support the same surviving receptor and expanding the command touches zero complete cells. With KT first, RR and RL share KT R. With KT second, RR and LR share KT R. Select the smallest supported time and SPW ranges; use residual baseline commands for mixed cases. A full-polarization flag discards the surviving samples in each partial cell. In this dataset all observed partial cells fit 12 antenna selections. Keep these calls under their own heading, individually written out.

If the export quality flags are also used, evaluate completeness again after those flags. The separate conditional list selects the complementary hands of each quality flag in its exact MS selection. Apply a complementary call only when applying its corresponding quality flag. On a different or edited MS, recompute the mask. The unaveraged channelized MS needs its own validity check per channel and integration; its scan-level diagnostic cannot supply those weights.

Use [full_polarization.py](../../../ancillary_py_codes/visibility/full_polarization.py) to generate the new plans before assembly. Use [verify_full_polarization.py](../../../ancillary_py_codes/visibility/verify_full_polarization.py) with CASA Python in each of two disposable working directories containing an imported MS named `M87_calibrated.ms` and a `.disposable_flag_test` marker. Pass the absolute path to the generated `full_pol_plan.json`, followed by the output audit path and mode. Use `full_pol_fresh.json fresh` for a pristine import. Use `full_pol_quality.json after-quality` on a second import after the 23 verified export quality flags. Save both audits in `M87_checkpoints/`. Run these audits before the assembler in step 7. Historical quality screens use the original half-open scan intervals so the previously reviewed commands remain reproducible. The updated plots and completeness mask use the inclusive endpoint tolerance. For each test, compare every output FLAG cell with the independent expected mask: each initially partial row must become fully flagged, each initially complete row must retain all four hands, and each empty row must remain empty. Record the incremental flag count and any mismatches before assembling the PDF.

This file has 149,400 records, 32 IFs, one frequency sample per IF and four circular products. It cannot give a 116-channel spectrum. |

Regenerate or verify their source identities before reuse. The PDFs and cached figures are outputs. |

For a new track, identify the corresponding source products before plotting. Prefer an actual calibrated channelized MS for fine data, with the correct visibility column, channel frequencies, flags, weights, source and scan. Establish agreement on the coarse grid before combining views. Validate signed channel ordering and multi-frequency setups explicitly. The included M87 readers implement the uniform single-setup case; adapt the extractor for other layouts. A UVFITS-only fallback must explicitly say “one frequency per SPW” where applicable. Never repeat a channel-resolved spectrum at a window center or synthesize frequencies to make a sparse export look fine-grained.

**Scan provenance.** Read UTC integration centers directly from DATE group parameters or MS TIME; report the first and last recorded centers per scan, including rows already flagged. If integration edges are needed, derive and label those separately using the integration intervals. Use an explicit scan column whenever present. Otherwise cross-check FIELD_ID, SCAN_NUMBER, TIME and interval from matching calibration solutions or the parent MS against visibility times. Sparse calibrator solutions cannot establish target exposure edges. Use the matching list.obs for original IDs where necessary, and record that source separately from the measured UTC. A gap-based segmentation without independent IDs must be labeled local. Validate a one-to-one assignment of records, including endpoints and midnight crossings. In this M87 UVFITS the only group parameters are UU, VV, WW, two DATE components, BASELINE and FREQSEL. Its original scan IDs need an external mapping. Keep the nominal bin anchor for reproducible time offsets even when it differs from the first measured timestamp.

## 10. Findings first, with a navigable index

Start with a title and observation line giving source, track/date, measured UTC coverage, scan and baseline–scan counts. Use these four headings in order. Continue opening material across as many pages as the evidence warrants; keep a heading with its first paragraph.

1. **What to inspect first.** Lead with two or three high-impact cases. For each give scan/time, station or ordered baseline, hand, comparison values with units or plotted scale, affected duration/frequency, control and proposed interpretation. For M87 the AA–PV and NN–PV opening RR amplitudes in scan 20 are 0.415 and 0.284 versus later medians of 0.013 and 0.012. AA–NN and AA–KT provide controls. The bright opening anchors the comparison. Contrast NN-specific channels recurring across partners with channel-115 edge spikes seen across the array. Recalculate all values and controls for each observation.
2. **Incomplete polarization coverage.** Give the denominator, partial/empty/complete counts, scans, missing products, stations and SPWs. Count jointly valid hands at native time/frequency resolution before averaging. Explain whether a station attribution survives independent partner tests.
3. **Plotted files and provenance.** Name the visibility, clock/ID source and diagnostic file pattern; explain what contributed to each view and what was unavailable. Give model metadata and analysis time.
4. **How to read the figures.** Explain evidence vs cleaned pages, units, native resolution and overlays. Put caveats beside the affected measurement. Document conditional commands and whether they are included in the displayed scenario.

Follow with an aligned **scan | measured start–end UTC | baseline count | valid complex samples before flags | available fine spectra | cleaned plot pages** table. Repeat column headings on continuation pages. A zero in “available spectra” must be distinguishable from zero valid visibilities. Below, **Selection and averaging** gives the weighting formula, cadence/binning, distinct frequency grids, missing hands, missing baselines and reasons a post-flag product might be unavailable. Compute physical page references only after opening material and evidence pagination are known; retain original scan IDs in bookmarks and plot titles.

## 11. Plot contract from the preferred full report

- **Symbol size and overlap.** Use round, unconnected Matplotlib markers with zero edge width: 1.9 pt diameter on weighted means and 0.78 pt on scan/channel spectra. For dense time samples use scatter area 0.42 pt², alpha 0.60 and no stroke. Shuffle valid samples across all hands with a reproducible permutation (seed 17) so the last hand drawn cannot hide the others systematically. Rasterize dense clouds at 220 dpi; keep labels, axes and annotation geometry vector. Use the same four colors in both sequences and a compact page legend of colored dots. Judge dense and sparse panels at normal reading size.
- **Axes and titles.** Use the reference 11.7 × 13 inch sheet; retain the 4 × 3 layout for the atlas. At each position put amplitude above wrapped phase, with a shared x axis and one horizontal title beneath the pair. Use GHz or seconds relative to a stated scan anchor. Directly label amplitude as mJy only for the Jy diagnostic converted by 1000; label the export as |V| × 1000 and document UNCALIB. Phase ticks are −180, 0, +180 degrees, with a little margin at the ends. Keep full peaks visible; add a fine horizontal grid, thin axes and short ticks; omit top and right spines. Put baseline, scan and domain above each pair and the UTC interval, baseline range, view and hands on the page. A fixed frequency range across a scan makes edge structure comparable.
- **Annotations.** Amber translucent spans identify suspect UTC intervals on both axes of a time pair. Pale blue marks a suspect window or coherent spectral slope; confine a phase-only feature to phase. Open dark rings around actual points identify isolated peaks; never cover the hand color with a filled symbol. For incomplete coverage put a magenta bar along the affected x intervals, with concise text such as “LL/LR missing in SPWs 17, 31”. Put the explanation between rows or in the footer. Other windows may still contribute those colors. In the cleaned atlas bars represent projected removed or withheld support; distinguish this meaning in the legend. Never draw the excised point to mark its former location.

## 12. Command evidence, then cleaned coverage

1. Freeze one numbered plan with exact target data grid, scan/UTC, antenna or baseline, hands, SPWs/channels, reason and disposition. Include the four-hand and conditional closure categories in the numbering. Use the same IDs in plots, captions, ledger and CASA appendix. Rebuild from the approved plan if reviewing a different set of decisions.
2. Render **before** data first, with one or two examples per command. Choose time for a dropout, IF means for a broad window problem, and true channel frequencies for a narrow peak. The current renderer ranks supported matching partners by selected valid sample count. Put two corroborating partners side by side for station-wide selections when possible. Use a stable control in the findings when it establishes attribution. Identify the target and exact selection, what triggered it, and any missing evidence; a command without recoverable evidence must remain visible as such.
3. Then render **all** observed baseline/scan pairs in scan order, with the original paired averaged/finer layout. Combine selections by union on the original ordered endpoints, timestamp, spectral grid and polarization. Recalculate both numerator and denominator of every complex mean after removing selected samples. Label empty panels and retain their places in the index. Annotate removals using command IDs, affected ranges and counts; distinguish exact flags from conservative display exclusions.
4. If a command selects a fine channel inside an unresolved exported IF, the residual IF average cannot be computed from that export. Withhold the contaminated IF/hand aggregate for the affected selection and say why. Conversely, a digitized scan spectrum cannot be recomputed after a partial time cut: withhold the affected SPW/hand of that spectrum. Other channels and hands can still be shown at their own frequencies. These withheld points are **not additional CASA commands**. With full time-resolved channel visibilities, apply the union directly and recompute the true residuals. Do not silently substitute a pre-flag scan diagnostic for a post-flag result.
5. The updated batch renderer writes separate evidence and cleaned sheets in `M87_checkpoints/review_plots/`. Its `--check-only` option validates selection expansion and constructs the residual arrays without creating PDFs. Before release verify every command ID and every baseline–scan pair, inspect representative sparse/dense/empty panels, reconcile pre/post valid counts, and match the printed CASA selections to the approved target-grid plan. The historical first-pass and second-pass PDFs in the isolated workflow test used a different renderer and UVFITS-only input; use the updated batch pipeline for the preferred layout.
