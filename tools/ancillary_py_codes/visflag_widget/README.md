# Visibility flag review

Review CASA flagging proposals against the visibility data you open. The browser widget opens the science data read-only. Approval writes individual CASA commands and their reasons to an ASCII file.

## Run on this Mac

From the checkout root, locate the shared widget and switch to the observation working directory. This example opens the sandbox M87 export with the archived visibility report. Use the same shell for the examples below.

```bash
widget_dir="$PWD/tools/ancillary_py_codes/visflag_widget"
visibility_report="$PWD/tools/instructions/examples/M87_full_visibility_inspection.pdf"
cd data/rpicard/e26m17_rpicard_sandbox/e26m17-1-b3 || exit 1
python3 "$widget_dir/app.py" M87_calibrated.uvf \
  --pdf "$visibility_report" \
  --output approved_M87_report.py
```

This writes `approved_M87_report.py` in `e26m17-1-b3`. Other relative output paths resolve in the directory from which you launch. If you launch from inside the code directory itself, relative outputs go beside the input data. An absolute `--output` always takes precedence. Expand **Data and output files** to see the resolved location.

To review an ASCII list instead of the PDF, use `--commands` (alias `--ascii`). Choose a separate output file:

```bash
python3 "$widget_dir/app.py" M87_calibrated.uvf \
  --commands approved_M87_report.py --output reviewed_M87_flags.py
```

Put one standalone, literal CASA `flagdata(...)` call on each line. Blank lines are ignored. Preceding `#` comment lines supply the reason for the following call. Each imported call becomes one review item in file order. Both previously exported approval files and hand-written lists are supported. Use the working MS path or its basename as `vis`. A UTC selection spanning several scans opens on a matching scan and retains its full time range.

For manual inspection, supply only the visibility file:

```bash
python3 "$widget_dir/app.py" M87_calibrated.uvf
```

The default output is `approved_flags.py`. Use separate output names for separate reviews. To resume, repeat the original command with the same output path. If an earlier version stored your review inside `visflag_widget`, specify that existing output by absolute path to resume it, or use a fresh file to begin again. Existing approved calls retain the targets you approved at the time.

### Two-pass human visibility review

From the observation directory, set the target basename to match the files generated by Codex. Keep each output separate so the first review remains available.

```bash
target=M87
python3 "$widget_dir/app.py" "${target}_calibrated.uvf" \
  --commands "${target}_Codexflag_commands.py" --output "${target}_Codexflag_commands_approved.py"
python3 "$widget_dir/app.py" "${target}_calibrated.uvf" --examine \
  --commands "${target}_Codexflag_commands_approved.py" --output "${target}_humanlag_commands.py"
```

In the first session, review the proposed commands on their matching data. In the second, examine all available scans and baselines, beginning with frequency-binned time plots, then time-binned frequency plots. Confirm every selection intended for the final export, including retained proposals.

### Start over with the same output filename

Add `--overwrite` to explicitly replace the chosen ASCII output and reset its companion review journal. All prior decisions in that output session are discarded at startup. For example, from the observation directory:

```bash
python3 "$widget_dir/app.py" M87_calibrated.uvf \
  --pdf "$visibility_report" \
  --output pdf_review.py --overwrite
```

Omit `--overwrite` on later launches to resume. The option also works in ASCII and manual modes. Close any widget that already owns the output before restarting it.

## Install elsewhere

From the directory containing `visflag_widget`, on macOS or Linux with Python 3.10 or later:

```bash
python3 -m venv .visflag-env
source .visflag-env/bin/activate
python -m pip install -r visflag_widget/requirements.txt
python visflag_widget/app.py --help
```

Alternatively use this Mac’s existing Python environment. A browser connects to the local server. Use `--no-browser` to open its printed URL yourself. UVFITS requires the Python packages above. Reading a Measurement Set also requires CASA. Set `--casa-python /path/to/CASA/python3` if CASA is outside the default Mac installation.

## Read the preview

Each of the four plots has **amplitude above phase**, with one shared horizontal axis labeled beneath phase. Phase always spans **−180° to +180°**. The top row shows time and the bottom row frequency. Native samples appear on the right. On the left, each time point is a weighted complex average over the selected frequencies in a time bin. Each spectral point averages over selected times and the specified number of adjacent channels within one SPW. Amplitude and phase come from the same complex mean. Amplitude uses the input scale (UNCALIB for the M87 UVFITS).

The **Before** view includes the input flags and previous approvals for the working data. The single **CASA flag command** box defines the preview. Enter one complete call per line. The mask is the union of those calls on the displayed baseline and scan; overlaps count once. Magenta circles identify selected native points and averages whose valid contributors are all selected. Amber squares identify averages with only some contributors selected. Editing or deleting a line refreshes the highlights. An invalid line clears the pending overlay, identifies its line number and disables approval until corrected.

Click **Show after flagging** to remove the selected samples from the preview and recompute the complex averages. Fully selected points disappear. Surviving points are drawn without selection markers. Click **Show before flagging** to compare at the same scales. The count of affected samples covers the whole displayed baseline and scan, across all four hands. The valid-in-view count applies the time, frequency and SPW view restrictions.

Click a polarization to hide or restore its dots across all eight axes. RR is red, RL green, LR blue and LL dark slate. The slider changes symbol size. Two left clicks in one axis set a zoom. A time zoom restricts the spectra, and a frequency zoom restricts the time plots. Clicking in amplitude also sets the amplitude range. Phase keeps its fixed range. **Zoom out** undoes one zoom and **Reset view** restores the full selection.

### Compare approved flags in the preview

The **Approved commands** panel on the right includes every approved call, even when several were approved together. Scroll inside the list to browse it independently of the plots. Each tinted group is labeled with the first station named in the antenna selector and its numeric ID. Groups follow the UVFITS antenna table’s NOSTA values or the zero-based MS ANTENNA row IDs. Commands within a group follow approval order.

Every call starts checked. Uncheck one to redraw the native samples and recompute the weighted averages with that call disabled. An input-flagged sample or one still covered by another enabled command stays flagged. Both before and after previews use the same checkbox choices. Choices persist while navigating in the current tab; reopening or reloading starts with all approved calls enabled. The ASCII output and review journal retain every approval. Finish an active outlier-picking sequence before changing the checkboxes.

## Pick individual outliers

**Pick outliers → click points → Finish picking → Pick outliers.** Set the zoom, visible hands, averaging bins and before/after view first. While picking, the plot is held fixed. Left-click in any amplitude or phase panel. Each click marks the nearest visible data point in screen coordinates. The status shows its hand and the number of distinct picks. For superposed products, hide unwanted hands before starting. Exact ties prefer the last-drawn visible hand; among coincident points of that hand the first matching sample is used.

| Clicked panel | Scope of one pick on this baseline and polarization |
|---|---|
| Time · Weighted averages | Integrations in the clicked time bin, across the selected frequencies |
| Time · Native samples | One integration and one spectral channel |
| Frequency · Weighted averages | Channels in the clicked spectral bin, across the selected scan times |
| Frequency · Native samples | One spectral channel and one integration |

The lower-right pair places every native visibility at its own channel frequency in GHz. MS input uses the per-channel `CHAN_FREQ` array. UVFITS uses the matching frequency setup, IF offset, channel spacing, sideband and reference pixel. Several integrations on one channel share the same x-coordinate. The distributed M87 UVFITS contains one recorded channel per SPW; open channelized visibility data to inspect finer frequency structure.

**Finish picking** appends individual CASA calls to the existing multiline editor. Your existing lines and reason are preserved. A time-only or frequency-only sequence of compatible picks can yield one call. Mixed time/frequency or averaged/native picks are grouped separately. Time ranges, spectral selections or hands are combined only when their other selectors agree. For example, two integrations in the same channel and hand can share a comma-separated UTC selection. Picking channel 1 at time A and channel 2 at time B produces separate calls to avoid flagging either crossed combination. Selected SPWs and zoom bounds constrain averaged picks. Use **Show after flagging** to inspect the result, then **Approve & append** to save it. Finishing with no picks adds no command.

## Review, approve and exit

1. In PDF or ASCII mode, the queue follows the printed commands. The widget displays a matching scan and baseline. For station commands, inspect other partners using the baseline menu.
2. Edit the CASA call and its reason. To create another call, use **Add flag selection**, adjust the antenna or baseline, scan scope, UTC timerange, SPWs/channels and correlations, then click **Append command**. The new call is appended on a fresh line in the same editor. The initial selection uses the current horizontal zoom and all four hands. Amplitude and phase thresholds do not enter a manual CASA selection.
   For mouse selection, click **Select to flag**, then left-click the two horizontal bounds in one time or frequency panel. Optionally select two bounds on the other axis to constrain both time and frequency. Click **Add flag selection…** to inspect the resulting coordinates and hands. **Append command** adds the selection without changing earlier lines. The displayed zoom stays in place.
3. **Approve & append** immediately saves all valid pending calls, in editor order, with the reason above each call as a comment, and advances. Invalid edits show an inline error. **Skip** advances without exporting the current commands.
4. **Skip all remaining & exit** asks once about ending the session. It preserves prior approvals, discards the draft, records the rest of the input queue as skipped, and stops the server. In manual iteration it skips from the current baseline through the final scan. To pause and resume a PDF review later, stop the server with Control-C instead. Committed decisions are saved; unapproved drafts are not.

## Which data a command targets

An opened MS is its own CASA target. For UVFITS, every newly exported call names the ordinary same-stem MS beside the UVFITS, e.g. `M87_calibrated.ms`. Before running those commands in CASA, ensure that MS is the matching import with the correct station and frequency metadata. Preview averaging affects only the display. The legacy `--native-ms` argument is accepted for old launch commands and does not change the output target.

An M87 report proposal for channel 115 cannot select that channel in the one-channel-per-SPW export. The widget keeps its channel selector, reports the missing match, and allows before/after comparison with **zero samples affected**. A mixed selection can still affect its matching channels. If you approve an unavailable channel, the ASCII file preserves that selector; CASA may report no match when you run it. To flag data on a finer grid, open the ordinary MS with that grid as the input. The optional report diagnostic shows the original scan-averaged spectral evidence.

For UVFITS, scan labels in the observing log can differ from numbers in the re-imported MS. Report selections using an original scan are translated to that scan’s UTC span before export. New UVFITS region selections likewise use UTC. For MS input, commands can use actual MS scan numbers. For report UTC selections, the widget checks the corresponding MS scan interval.

## Manual mode and supported input

Select a scan and baseline, enter SPWs (blank for all, or e.g. `17,31`, `5,8~9`, `3:10~20;25`), then set the time bin in seconds and channels per spectral bin. The initial template supplies the working MS and manual mode. Fill its selection fields or use **Add flag selection**. Choose any **Scan** from the dropdown to open its first baseline, or jump directly with **Baseline**. **Next** and **Previous** browse without exporting a flag. At a scan boundary they continue to the adjacent scan; at the ends of the dataset the corresponding button is disabled. To start a flag from scratch, click **Select to flag**, pick the bounds, choose **Add flag selection…**, then **Append command**. **Approve & append** writes the call and your reason to the ASCII output. **Advance after approve or skip** starts enabled in a fresh manual session. Clear it to stay on the current baseline after a decision.

UVFITS input uses standard single-source, single-frequency-setup AIPS random groups with circular correlations. The visible **Scan IDs** line names the numbering source. The widget first reads explicit per-visibility SCAN, SCAN_NUMBER or SCAN_ID parameters (also accepting spaces or hyphens), or an explicit scan-ID column in an AIPS NX index with one-based START VIS and END VIS ranges. An ordinary NX row number alone cannot establish the original CASA scan ID. Embedded IDs take precedence over --scan-log. Conflicting or malformed embedded IDs stop the load. Without explicit IDs, pass the matching list.obs with --scan-log or allow the widget to discover sibling diagnostics logs. Conflicting complete log mappings require an explicit choice. With no log, time gaps longer than --scan-gap seconds (default 60) produce local browsing labels. For this fallback, imported scan selectors require a matching log. A PDF item can still be located by an unambiguous UTC selection, and manual UTC selections remain available. MS input uses the FIELD table, stored visibility flags, and weights. For multiple fields, specify `--field M87`.

Keep the ASCII output and its companion `.review.json` together. The journal records progress; a lock prevents concurrent writers. CASA commands are parsed as literal manual selections and are never executed by the widget.

## Review a single-band fringe calibration table

Launch from the reduction directory. Use the regular widget Python environment for the application and CASA Python for reading the table.

```bash
python3 "$widget_dir/app.py" calibration_tables/ff_sb.t \
  --casa-python "$HOME/Applications/CASA-6.6.6-Intel.app/Contents/MacOS/python3" \
  --output approved_ff_sb.py
```

Opening a `.t` directory selects fringe mode. This mode supports the rPICARD circular-feed Fringe Jones layout with eight real parameters, one solution channel and a unique row per antenna, scan and SPW. The delay overview opens first. The button names the view it will open. For the selected antenna it shows a separate delay-versus-frequency row for each observed source, overlaying all scans without averaging them. Hover over a point to see its scan, SPW, hand and delay. Pick outliers directly, or use **Form scan** to select a specific scan when points coincide. Changing Form scan only targets the selection form. Approve and Skip antenna advance to the next antenna in this view.

Click **Delay and phase** for the single-scan view. From that view, click **Delay only** to return to the all-scan overview. In **Delay and phase**, select an antenna and scan from the menus or step through each with the arrows. The upper panel shows delay in ns. The lower panel shows phase wrapped to −180° through +180°. Both use the same frequency axis in GHz, at each SPW’s mean observing frequency. The delay panel shows the finite, unflagged solutions for the selected antenna and scan. It displays “delay is fully flagged” when every delay is flagged. Each hand/SPW shows phase when its own delay and phase are both finite and unflagged. Labels list unavailable delays and phases by hand and SPW, including compact ranges. Checked approvals and the after-flagging preview follow the same rule. Hiding a hand or zooming changes only which points are visible. R uses blue circles and L uses orange plus signs. Toggle either hand to pick overlapping points. **Zoom range** takes two left clicks defining shared frequency limits.

Choose **Pick outliers**, click solutions, then **Finish picking**. Alternatively, choose SPW, hand and parameter and click **Add flag selection**. Each selection appends one editable line with the absolute path of the loaded table in `vis`. The export contains only standalone `flagdata(...)` calls, each with its own table path. Review reasons are saved in the companion journal. The magenta outline tracks the current selection. **Show after flagging** hides the selected parameters in preview. Add a reason and click **Approve** to export and advance. **Skip scan** discards the draft. **Skip remaining and exit** preserves prior approvals. The approved list lets you temporarily restore hidden points by unchecking a selection. Reopen with the same input and output to restore approvals. Supply `--overwrite` to start over.

Run the approved file in a CASA session with `flagdata` available. To apply it to a copy, change the literal table path in each call first. For R phase and R delay the widget uses CASA clip mode on FPARAM, selecting REAL_Sol1 and REAL_Sol2 respectively. One antenna, scan and SPW identify the row. The broad clip interval includes the chosen parameter value, including zero. In this CASA version the Fringe Jones flagger exposes the first four slots only. L phase and L delay (slots 5 and 6 in CASA’s one-based numbering) can be plotted, but selecting them displays a message explaining why an exact flagdata command is unavailable. Existing helper-based exports and their journals can be kept by choosing a new output filename.

To repeat the integration check, run from the observation directory:

```bash
python3 "$widget_dir/test_fringe_copy.py" calibration_tables/ff_sb.t \
  "$HOME/Applications/CASA-6.6.6-Intel.app/Contents/MacOS/python3"
```

The check creates a temporary copy, exports R-phase and R-delay approvals through the review backend, executes that script on the copy and compares the complete FLAG arrays.

## Review passband solutions

From the observation working directory, open either table or both together. Use a separate output from any fringe or visibility review.

```bash
python3 "$widget_dir/app.py" calibration_tables/bpass_complx.t --output phase_flags.py
python3 "$widget_dir/app.py" calibration_tables/bpass_scalar.t --output amplitude_flags.py
python3 "$widget_dir/app.py" calibration_tables/bpass_complx.t calibration_tables/bpass_scalar.t --output passband_flags.py
```

The widget recognizes the rPICARD table names above. Use `--casa-python /path/to/CASA/python3` on another installation. **Previous**, **Next**, and the antenna menu switch stations. A single table gives one panel per hand. With both tables open, each hand has a phase panel followed by an amplitude panel. Phases are in degrees and amplitudes are dimensionless. Each point uses its native channel frequency in GHz. Alternating blue and white intervals follow SPWs in frequency order. The pointer readout gives the frequency, height and SPW.

Plots include all finite, unflagged solution rows for that antenna. Coincident values at the same channel are drawn once. Counts include every contributing row. Each table supplies its own frequencies, flags and solution rows.

- Click **Clip above** or **Clip below**, then left-click at the desired height in one panel. This appends a formal CASA command for that table, antenna and hand across **all SPWs and solution rows**, including channels outside a zoomed view. Each further click adds another selection. The threshold appears in the command as radians for `ARG_Sol1/2` and dimensionless gain for `ABS_Sol1/2`.
- **Pick SPW** then left-click inside a spectral window to select every channel in that window for the displayed antenna, table and hand across its solution rows. The exported CASA call uses a single SPW ID.
- **Pick channel** selects the nearest plotted channel when you click its point. The command applies to that hand, antenna and SPW/channel across its solution rows. The other table has independent flags. To restrict a threshold to specific channels, add a literal CASA SPW selection such as `spw='28:86~89'` to that call.
- Edit the individual commands to update the magenta highlights, then use **Show after flagging** to preview the resulting spectra. **Zoom range** uses two left clicks for shared frequency limits. **Zoom out** restores the full band.
- Add a reason and click **Approve** to save the draft and advance. **Skip antenna** discards the draft. Approved commands can be unchecked in the right panel to restore their samples temporarily. **Skip remaining and exit** retains existing approvals. Restart with the same tables and output to restore approvals, or add `--overwrite` to reset the review.
- The ASCII output contains only standalone `flagdata(...)` calls. The companion journal records the reasons. The widget opens the science tables read-only. Running the approved commands in CASA applies the flags to their literal table paths.

The copy test exercises both clip directions, both hands, the reference station selector and a channel pick. It compares CASA’s full output flag cubes against independently calculated selections.

```bash
python3 "$widget_dir/test_bandpass_copy.py" calibration_tables \
  "$HOME/Applications/CASA-6.6.6-Intel.app/Contents/MacOS/python3"
```

## Import a report or ASCII list and examine other data

Use either `--pdf` or `--commands` (also `--ascii`). The default import opens one proposed command at a time, prefills the editable command and available reason, and shows the corresponding data. **Approve** exports the reviewed selection. **Skip** advances without exporting it. Resume an interrupted queue with the same inputs and output.

```bash
# Review both passband tables using the calibration report
python3 "$widget_dir/app.py" calibration_tables/bpass_complx.t calibration_tables/bpass_scalar.t \
  --pdf inspection/passband_Codexflag_summary.pdf --output reviewed_passbands.py

# Review the single-band delay report
python3 "$widget_dir/app.py" calibration_tables/ff_sb.t \
  --pdf inspection/delay_Codexflag_summary.pdf --output reviewed_delays.py

# Browse every antenna with the passband ASCII proposals available
python3 "$widget_dir/app.py" calibration_tables/bpass_complx.t calibration_tables/bpass_scalar.t \
  --commands reviewed_passbands.py --examine --output examined_passbands.py

# Browse every baseline and scan with visibility proposals available
python3 "$widget_dir/app.py" M87_calibrated.uvf \
  --pdf "$visibility_report" --examine --output examined_vis.py
```

**Command review** follows import order. A passband proposal opens its antenna, table and hand. A fringe proposal opens the antenna and a scan within its selection. The scan menu permits stepping through its scan range. The command keeps the entire range when approved. Passband phase plots can highlight channels selected by a modulus clip in the complex table. When only one passband table is open, the widget reviews commands for that table and reports the number omitted for the unloaded companion.

**Examine** uses the normal data navigation and prefills applicable proposals when you arrive at matching data. You can add selections on plots with no proposals. Visibility mode permits every observed baseline and scan. Passband mode permits every antenna and panel. Fringe mode permits every antenna and both the scan and source-overview displays. Suggestions retain their original scope, including other scans or baselines covered by an antenna command. With no import, `--examine` has no effect. Choose separate output paths for command review and examine sessions.

Calibration PDFs should follow the examples above. The widget reads active literal `flagdata(...)` calls and resolves report table aliases to the actual tables opened. Commented examples, imports, and report copy/setup instructions do not run. Calibration ASCII input accepts literal `flagdata(...)` calls with table paths and preceding reason comments. New outputs contain individual formal CASA commands.
